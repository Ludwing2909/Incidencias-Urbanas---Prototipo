Las cifras provienen de `reports/runs/demo-v3/experiment.json`, no son metas ni rendimiento local.

Ocho casos funcionales elaborados independientes: accuracy 0.875 y macro-F1 0.833; soporte de solo un caso por clase, insuficiente para conclusiones. Catorce desafíos elaborados se reportan separados, con tema conocido o nulo. No hay validación real, prueba real ni corpus local. Por ello el umbral es null, cobertura de sugerencias habilitadas cero y exactitud selectiva no calculable. Las reglas demo no validadas bloquean competencias; C7/C8 siempre revisión. Los JSON, matrices, curvas y errores de cada ejecución son la referencia técnica completa.

Solo usa texto redactado mediante Pipeline común. Fuente/destino/estado/contacto no son variables. TF-IDF se ajustó por pliegue dentro del entrenamiento. No se adoptaron stopwords ni corrección ortográfica. Demo tiene tildes, negaciones y algunos términos habituales, pero no revisión lingüística local; no existe soporte validado quechua/aimara.

Riesgos medidos/propuestos: vocabulario fuera de distribución, casos múltiples, nombres residuales, negaciones de urgencia y fallos de heurísticas. Una probabilidad alta no demuestra pertenencia al alcance. En producción inicial se revisan textos sin pistas conocidas, múltiples temas, texto insuficiente, idioma reconocido fuera de alcance, baja puntuación o falta de reglas/competencia. Las heurísticas de idioma/urgencia son limitadas y tienen falsos positivos y negativos documentados.

Versionado: hashes de dataset/artefacto/keywords, semilla, etiquetas y orden, dependencias, parámetros, calibración, IDs/grupos/pliegues, umbral y fecha UTC. Activación explícita conserva modelo anterior. Correcciones no reentrenan; deben adjudicarse en nueva versión de datos. Mantener la evaluación independiente por versión y no usar indefinidamente el mismo test para selección.
